# Optional setup and operation

## Existing local model server

The application currently accepts loopback HTTP only. It needs OpenAI-style chat
completions plus llama.cpp-compatible token counting and context behavior; a
random compatible-looking endpoint is not enough. Keep one inference slot and
8192 context. The supplied `start_chat.py` uses a local manifest generated by setup.
No auto-start LaunchAgents from the developer's machine are included.

## Images and voice

```sh
uv run --extra setup scripts/setup_local.py --images
uv run --extra setup scripts/setup_local.py --voice
```

Images use a separate MFLUX environment, download weights on demand, and may require
additional disk/RAM or model access approval. Public example uses Z-Image Turbo;
no particular content capability is promised. Voice uses whisper.cpp, ffmpeg and
macOS speech synthesis. An image request may be explicit (`/photo`, `/selfie`,
`/image`) or interpreted from chat. Settings are not model requests.

## Telegram settings panel

Inline settings buttons work without a public website. The optional Mini App uses
127.0.0.1:8767 inside the bot when enabled and needs an operator-controlled HTTPS
proxy. Never expose model ports, workbench, Prompt inspector or databases through
that proxy. Mini App authentication uses Telegram initData and the allowlisted user.
A fully automatic public tunnel installer is intentionally not bundled.

## Records

`.data/telegram/memory.sqlite3` stores conversation/state; diagnostics.sqlite3 stores
full model request/output traces. The Prompt inspector reads those databases in
read-only mode. Never share a real data directory in an issue. Start with the
synthetic demo to share a UI example safely.

Use `/settings` for life/proactive/quiet hours and current clothing. The sample
profile starts with proactive messaging off; enabling it can send real Telegram
messages. Keep the Mac awake if unattended operation is desired.
